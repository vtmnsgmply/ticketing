# Customer Dashboard Module

## Objective

Build the Customer Dashboard and customer-facing ticket experience for the Ticketing System.

Before making any changes:

1. Read `1. AGENTS.md`.
2. Review the completed implementation from:
   - `2. LOGIN.md`
   - `3. TICKET.md`
   - `4. ADMIN.md`
3. Inspect the existing `frontend` and `backend` code before modifying anything.
4. Preserve the existing authentication, authorization, ticket logic, admin functionality, database structure, and API conventions.
5. Reuse existing services, repositories, models, routes, components, and utilities where appropriate.
6. Do not duplicate working functionality.
7. Follow the required backend architecture:

```text
User Request
    ↓
Route / Controller
    ↓
Request
    ↓
Service
    ↓
Repository
    ↓
MySQL
```

Controllers must remain thin.

Validation belongs in the Request layer.

Business logic belongs in the Service layer.

Database access belongs in the Repository layer.

---

Build the customer-facing portal with the following functionality:


# Security Requirements

- Enforce Customer role permissions on the backend.
- Scope all Customer ticket access.
- Hide internal notes at API level.
- Protect attachment downloads.
- Do not trust customer-supplied `customer_id`.
- Validate all incoming data.
- Prevent insecure direct object references.
- Prevent stored XSS in ticket messages.
- Safely render user-generated content.
- Use secure password handling.
- Do not expose stack traces.
- Do not expose database errors.
- Do not expose internal file paths.
- Use CSRF protection where applicable.
- Use secure authenticated API requests.
- Rate limit sensitive endpoints where appropriate.
