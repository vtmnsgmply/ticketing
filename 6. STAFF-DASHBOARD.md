# Staff Dashboard Module

## Objective

Build the Staff / Agent Dashboard and operational ticket-handling workspace for the Ticketing System.

Before making any changes:

1. Read `1. AGENTS.md`.
2. Review the completed implementation from:
   - `2. LOGIN.md`
   - `3. TICKET.md`
   - `4. ADMIN.md`
   - `5. CUSTOMER-DASHBOARD.md`
3. Inspect the existing `frontend` and `backend` code before modifying anything.
4. Preserve the existing authentication, authorization, ticket logic, admin functionality, customer portal, database structure, API conventions, and UI conventions.
5. Reuse existing Services, Repositories, Requests, models/entities, routes, components, and utilities where appropriate.
6. Do not duplicate working functionality.
7. Follow the required backend architecture:

```text
User Request
    ↓
Route / Controller
    ↓
Request
    ↓
Service
    ↓
Repository
    ↓
MySQL
```

Controllers must remain thin.

Validation belongs in the Request layer.

Business logic belongs in the Service layer.

Database access belongs in the Repository layer.

# Staff Access Rules

The Staff / Agent role must have access only to tickets and actions permitted by backend authorization rules.

Recommended role:

```text
Staff / Agent
```

Recommended slug:

```text
agent
```

Staff must not automatically receive full administrator or manager access.

Staff must never access:

```text
Admin-only configuration
User role management
System settings
SLA configuration
Email settings
Global audit logs
Other departments unless permitted
Manager-only reports
Sensitive system-level settings
```

Backend authorization is mandatory.

Do not rely only on hiding controls in React.

# Assignment / Reassignment

Staff assignment permissions must follow business rules.

Possible initial rule:

```text
Agent:
- Can assign an unassigned ticket to self.
- Cannot freely assign other agents unless permitted.

Manager:
- Can assign/reassign within managed scope.

Administrator:
- Can assign/reassign broadly.
```

If Staff is allowed to assign other agents, validate the target agent:

```text
Active account
Agent/Manager role where appropriate
Allowed department
Eligible for assignment
```

Do not trust an arbitrary `assigned_agent_id`.

