# Manager Dashboard Module

## Objective

Build the Manager Dashboard and supervisory workspace for the Ticketing System.

Before making any changes:

1. Read `1. AGENTS.md`.
2. Review the completed implementation from:
   - `2. LOGIN.md`
   - `3. TICKET.md`
   - `4. ADMIN.md`
   - `5. CUSTOMER-DASHBOARD.md`
   - `6. STAFF-DASHBOARD.md`
3. Inspect the existing `frontend` and `backend` code before modifying anything.
4. Preserve the existing authentication, authorization, ticket logic, admin functionality, customer portal, staff portal, database structure, API conventions, and UI conventions.
5. Reuse existing Requests, Services, Repositories, models/entities, routes, components, and utilities wherever appropriate.
6. Do not duplicate working functionality.
7. Follow the required backend architecture:

```text
User Request
    ↓
Route / Controller
    ↓
Request
    ↓
Service
    ↓
Repository
    ↓
MySQL
```

Controllers must remain thin.

Validation belongs in the Request layer.

Business logic belongs in the Service layer.

Database access belongs in the Repository layer.

# Manager Access Rules

The Manager role must have broader operational access than Staff / Agent but less system-wide administrative control than Administrator.

Recommended role:

```text
Manager
```

Recommended slug:

```text
manager
```

Managers may generally:

```text
View tickets within managed departments
View team queues
Assign and reassign tickets
View unassigned tickets
View overdue tickets
View high-priority tickets
Monitor SLA
Review team workload
Review basic performance summaries
Change ticket status where permitted
Change ticket priority where permitted
Add internal notes
Reply to customers where permitted
Review ticket activity
```

Managers must not automatically receive access to:

```text
Global Admin settings
User role administration
System settings
Email credentials
Global audit configuration
All departments outside their assigned scope
Infrastructure configuration
```

Backend authorization is mandatory.

Do not rely only on frontend visibility.
